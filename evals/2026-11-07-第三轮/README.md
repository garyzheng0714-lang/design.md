# 2026-11-07 第三轮：同一题用改过的技能重做

题目 `brief.md`、规则 `RULES.md`、数据 `expo.ts`（FBIF 展商权益交付的「展商」这一屏）。两个全新的无头 Claude（Opus 5.5）各做一份：w、x。用户看完 w 说「W应该是目前最满意的一版，其他可以不用测了」，x 中途停掉。

`w-用户看过的版本/` 是用户看的那一版源码，**这道题的参照**（总纲 §2）。之后那次运行又改了一个小时（翻页提速、催办方式跟着内容自动选、时间线……），用户没看过，不存。

## 用户的意见（原话）

做得好的：「你做的好的一点是：你首先有渐进式披露」。

要改的：
- 上一家 / 下一家：「这个下一个和上一个，是你完全臆想出来的操作。……实际情况下，如果是我，我会在这边放一个叫做“催办”的评论区。这样不管在这个抽屉的任何页面，我都可以随时记一条催办和日志，对吧？」
- 点分隔（截图里「D07·孙婷负责」）：「我极其极其极其极其讨厌任何情况下文字中间给我加一个点来做分割，而不是用设计或者组件来做。永远不能再出现这样的设计！……在我眼里这是一个非常严重的偷懒行为，说明你对我说的“布局优先于文字”理解还是不够到位。我觉得这应该作为第一条红线：布局优先于文字理解，用布局自己去说话，而不是靠文字去描述」
- 侧栏：「我讨厌这个侧边栏的设计，完全让人摸不着头脑，也不知道要干什么，我只能说设计得很恶心」
- 数数写成句子：「像“全部展商已交付 53-125 项”，你又在这里用纯文字去描述；“1 到 14 共 28 家”，又是用文字描述。……比如像“逾期权益 6 项 6 家”诸如此类的表达，我是极其讨厌的。我不是讨厌别的，我是讨厌明明有更好的呈现方式，你却没去找」
- 披露过头：「“审核通过”、“收到物料”这些操作，你把按钮直接呈现出来会怎么样呢？非要给它隐藏起来」
- 表格：「这表格也很丑，字段七七八八的都没办法调整」
- 方法：「很多设计法则、人家现成的 skill 让你去参考，你也不去参考，自己在那里乱搞」
- 流程：「我觉得一个好的流程应该需要这样两个智能体：1. 监工子智能体……对每一个操作细节和交互做审核，看是否已经用了更合适的组件、是否还有更合适的组件可以用，而不是偷懒。……2. 用户体验智能体：它应该负责体验层面的东西，自己去乱点，怎么点都行，想办法让客户用最小的步骤完成任务。多一步就是比少一步差（某种情况下来说是这样，但不包含特殊情况）」

## 这些错从哪来（查过）

- 上一家 / 下一家：出自题目第 5 条（我写的）和当时总纲 §3.2「详情里有上一个 / 下一个」，不是做页面的智能体自己想的。题目已改：第 5 条去掉，第 7 条改成「看这家展商的任何时候都能随手记」，场景 S8 换成「不开详情直接推进」。
- 「1–14，共 28 家」这类：出自当时布局手册里翻页条的写法。已删。
- 方法：运行记录里读过总纲、rules、mockup、layout、build、stageshow、heroui-react，**一份 better-* 和 Emil 都没读**；Mobbin 搜了 3 次。
- 侧栏放范围、主按钮藏起来：出自当时布局手册「范围 ≤ 7 放侧栏」和「行内操作指向才出现」。已改。

## 改了什么（插件 2.0.3）

- 总纲：红线 1 换成「布局优先于文字」（点分隔、数数句、说明句都在里面），红线 2 换成「渐进式披露，但不藏主要动作」；§3.2 详情底部放催办评论区、不做上一个 / 下一个；§3.4 侧栏只放导航；列宽能调；§10 加这几条讨厌。
- 机器查：改后检查退回点分隔（· • ・ 和它们的实体、转义）和「共 N 条」；探针量表格列距、长名单没翻页。
- 两个子智能体：`plugin/agents/supervisor.md`（监工）、`plugin/agents/ux.md`（体验员，带乱点脚本 `scripts/explore.mjs`）。
