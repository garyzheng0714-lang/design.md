## 横向结论

- 布局最好：G 和 C。页头有重心，进度只画一次、只画当前范围，名单铺满到底。
- 交互最好：B。新增是插一行而不是弹表单；详情不遮名单、点别的行就换人；改值时数字滚动、席位换色，原位看得到结果。
- 组件用得最好：C。Select inline、Drawer 宽屏右出 / 窄屏底出、DatePicker、弹簧进度条，没有手搓也没有原生控件。
- 最大的共性问题：7 份都是「侧栏 + 页头 + 全字段表格 + 右抽屉」，只有 B 和 E 在进度和新增上想出了这件事独有的形状。4 份切论坛时会跳；4 份用 toast 复述结果。

如果把长处拼成一份，这一屏应该这样：
1. 左栏：「全部论坛」+ 7 个论坛。每行是名字 + 一根带「2/8」的细进度条（D 的可读性，但只占一行高），选中项用托起的白底。窄屏顶部换成「当前论坛 ⌄」下拉（D）。
2. 页头只有一行半：大号论坛名（G）+「已确认 n / m」，旁边是搜索和「新增嘉宾」。下面放这个论坛的席位条（B 的格子，进到论坛后格子上写人名，可以点，借 E）。席位条只画当前范围，不重复左栏。
3. 名单：表头吸顶、首列冻结且不截断人名、字段照数据源顺序（G），状态用 inline Select + Tag 就地改。改完原位滚动换字，席位格同时换色（B / C）。
4. 新增：名单顶上插一行空白嘉宾并选中，详情面板打开、论坛预填，不弹表单，不弹 toast（B）。
5. 详情：非模态面板，从右侧滑入（不只是淡入），不加遮罩，名单能继续点（B / E）。顶部流程条用灰 / 黄 / 绿，可以点；基本信息、联络日志、联系方式往下直接展开，不进 Tabs。日志「写了字才露出日期 / 方式 / 记下」（A），新记的一条用 layout 插入（G）。底部钉「上一位 / 下一位」（F）。窄屏同一个面板改成从底部出（C）。
6. 切论坛：整块淡入或带方向滑入（C），不能出现空行跳动；进度条和席位都用弹簧过渡。
