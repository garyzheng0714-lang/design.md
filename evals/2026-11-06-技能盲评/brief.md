# 题目：FBIF 嘉宾邀请工作台 ·「演讲嘉宾」这一屏

## 谁、做什么

FBIF（食品饮料创新大会）的内容策划同学，每天打开它推进 2027 届大会几十位演讲嘉宾的邀请：看各分论坛邀到哪了、催进度、改状态、记联络。电脑上用为主，路上偶尔用手机看一眼。一天里会反复打开很多次。

## 功能清单（全部来自用户过去的原话，就这些，不多做）

1. 看所有分论坛的邀请进度：每个论坛已确认几位 / 计划几位，以及总进度。（「我的概览页呢？看所有论坛进度的。」「论坛这边就是显示进度就好。可以有一个总进度。」）
2. 切换分论坛，只看这个论坛的嘉宾；当前看的是哪个论坛要一眼看得出。（「我左侧切换分论坛的时候，顶部应该有明显的显示」）
3. 嘉宾名单：有表头、往下滚表头不消失；首列（演讲嘉宾）固定、不要太宽；字段尽量多显示，用原表格的叫法；显示全部，不分页。（「列表为什么没有表头？」「首列冻结固定」「你的首列为什么那么宽」「嘉宾不应该说只显示 50 条，而是要显示全部」）
4. 在名单里直接改「邀请状态」，不用进详情。（「预期我是可以直接在状态列编辑的」）
5. 点一位嘉宾看详情：浮在名单上方、不挤压名单，有一点阴影表示层级，点空白处收回；顶部横向显示这位嘉宾的邀请流程走到哪一步，节点能点（未开始灰、进行中黄、完成绿）；详情里分区：基本信息、联络日志、联系方式；名单里的字段在详情里同名、能改；能切到上一位 / 下一位。（07-12、07-13、07-17、07-23、07-25 原话）
6. 在某个分论坛下新增嘉宾，自动带上这个论坛。（「可以直接预填这个论坛的名称」）
7. 给一位嘉宾记一条联络日志（日期、方式、内容）。
8. 按名字或公司找到一位嘉宾。

## 数据

`import { FORUMS, GUESTS, STATUSES, FLOW, OWNERS, ME, TODAY, type Guest, type Forum, type Status } from "~bench/data/fbif"`（文件 `/tmp/skill-bench/app/src/data/fbif.ts`）。7 个分论坛、37 位嘉宾、每位有联络日志。字段：演讲嘉宾、公司、职位、分论坛、邀请状态、负责人、演讲话题、最近联络、手机、邮箱、微信、联络日志。值可以在页面里本地改（React 状态），字段不增不减、不改叫法。

## 屏幕

1440×900 电脑，390×844 手机。两个宽度都要成立。
