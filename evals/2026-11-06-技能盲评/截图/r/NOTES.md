# r · 照 frontend-design 做的步骤

1. 先定主题：FBIF 的策划同学一天打开很多次，推进几十位演讲嘉宾。行业里的说法是「议程、会期、厅、席位」，主要的活是「看哪个论坛还缺人，然后去催」。
2. 定调性和记忆点：克制的工作台，大胆只用在一处，就是**席位**。每个论坛计划请几位就画几个座位：已确认的坐实（绿），在谈的虚坐，剩下的是虚线空位。总进度和每个论坛的进度都用同一套座位语言，不用「大数字加进度条」那种默认做法。
3. 先出方案再对照题目检查：最初想的是概览卡片网格加单独的进度页，这正是 SaaS 套件的默认做法，所以改了：进度并进左栏行尾，总览用一条按论坛分组的座位条，进了某个论坛，座位上直接写人名。
4. 写代码，然后截图自查了 3 轮：改了状态格竖向没对齐、首列双倍缩进、窄屏总览太高（改成横向滚动）、详情遮罩把名单模糊掉（改成非模态，见下）。
5. 写字照技能的写作那一节：不加眉标，不用全大写，不加「→」，元信息不用中间点串起来，文案只留动词和字段名。

## 没照做的地方和原因
- 字体、配色、背景氛围：测试规定皮肤固定用 Su，所以不换字体、不加纹理。
- 「进行中黄」：Su 的 warning 变量是实墨色（黑），没有黄色变量，所以沟通中是实心墨点，已邀请是空心墨点，流程里进行中那一步是墨色实心。规则说不能自定配色，题目原话里的黄色就没做。
- 新增嘉宾用的是模态抽屉（带遮罩）：表单填到一半，点外面不该丢掉。详情抽屉是非模态。
- 搜索只在当前范围里找；当前论坛搜不到时，给一个「在全部论坛里找（N）」按钮。

## 布局（5 行）
- 分区：左栏 Sidebar 是分论坛，按会期日期分组（NavSection），每行 NavItem 行尾是座位小条加「已确认/计划」；顶部是当前论坛的大标题、日期和厅，搜索（SearchField）和「新增嘉宾」（Button）在右边；标题下面是座位行；再往下是名单。
- 主次：座位行（总览时是 7 组座位条，点一组进那个论坛；进论坛后是写着人名的座位，点人名开详情）是这页让人记住的一点，其余保持安静。名单用 Table，在自己的滚动区里，表头吸顶，首列（演讲嘉宾，128 宽）吸左，11 个字段全部显示，不分页。
- 名单里改状态：邀请状态格是 inline Select，用圆点区分状态。
- 详情：右侧非模态 Drawer，浮在名单上、不压暗也不挤名单，点空白收回；名单开着时直接点另一位就换人，当前那一行高亮。从上到下是：所在论坛和位次「第几位 / 共几位」加上一位、下一位，可点的 4 步邀请流程，基本信息（Input / Select / DatePicker，和名单字段同名），联络日志（「记一条」就地展开：日期、Segmented 选方式、Textarea），联系方式。
- 动效只在响应操作的时候出现：状态改成已确认时，座位用 layout 弹簧换到前面；流程连线用 scaleX 弹簧；日志编辑框展开收起、新日志落位；抽屉和表格行用组件自带的动效。没有页面加载动画。
