# 方案图：定这一屏 → 先例 → 定骨架（layout.md）→ 方案图（stageshow）→ 评审

用户 2026-11-02：「画线框图的流程可以去掉了……不需要先画线框图，你就按照我们 STAGESHOW 的 skill 来」；同日：「把这个 skill 也内化到我的 su-design 里……一切都以他为准。」（su-design 是这个技能 11-07 之前的名字。）
插件的 `precedent-gate` 钩子会核对：本会话从头到尾读过总纲 DESIGN.md、[rules.md](rules.md) 和一份流程（本文件、build、polish、motion 或 connect）、Mobbin 至少 2 次搜索且合计 ≥ 10 张图，否则不让写界面文件；HeroUI 项目（或还没换的 `@su` 旧项目）里新建页面或整页改版（方案图本身也算），本会话没从头到尾读过 [layout.md](layout.md)，或没做过方案图（没写过含 `<Stage` 的代码），也拦下。只改逻辑的编辑不拦；用户说「跳过先例」两道都放，「跳过方案图」只放方案图、布局手册照读。

## 1. 定这一屏

写一句：**谁、来做哪一件事（一个动词）、做完去哪**。需求里有几个动词，就先看人家怎么拆（分页、主次、抽屉、「⋯」），不先拼进一屏。改已有页面：先列出每块在干什么，哪块不属于这件事。

再列**功能清单**：用户原话里的每个动作一行，这就是全部。之后每加一个控件，都要对得上清单里的一行；对不上的不做。改已有页面：先把原页面的数据、字段、动作抄成清单，交付时逐项对上，一样不少、数值不改。

## 2. 看先例（Mobbin `search_screens`，每次 12–20 张）

- 整屏：同一任务的整页（`web`；有移动端再搜 `ios`）。
- 部件：这一屏每个部件各搜一次（筛选和搜索贴着谁、行操作、新建入口、空状态、详情从哪打开）。
- 之后：做完这件事的下一屏（生成后结果出现在哪、点一行去哪、删除后怎么撤回）。交互逻辑从这里看。
- 查询写「人在做什么」（`paste a long URL to create a short link, recent links below`），不写组件名和风格词；结果不像就换说法，用 `exclude_screen_ids` 去掉看过的。每张都看。
- 挑 3 张最贴近的（不同产品），每张拆一行：分区与宽度；标题写什么；主动作在哪、叫什么；筛选贴着谁；数据怎么排（表头、列、对齐）；详情 / 新建怎么打开；收起了什么。
- 写「共性 → 我们的做法」：≥ 2 张一致的是底线，我们不能比它差；只有 1 张的说出理由再用。共性只管结构和交互的下限，这一屏独有的形状、披露和因果在下一步定。
- 先例给结构，不给功能：先例里有、清单里没有的（忘记密码、记住我、批量操作、导入导出、改后缀……）记进「没做」，交付时一句话提出，不做。

## 2.5 定骨架（从头到尾读 [layout.md](layout.md)，照它写下面六样，这就是本页规格）

1. 姿态：一行（总览、名单、队列、编辑、设置之一）。
2. 三版骨架：A 先例版、B 形状版、C 少一层版各一行，再写「选哪版、借了什么」。
3. 形状：这一屏的每种数据画成什么（layout.md §3），第一层至少有一处形状，不是一串数。
4. 区域 → 组件：每块用哪个 HeroUI 组件（[rules.md](rules.md) 边界 4；它没有的照 [connect.md](connect.md) 拼或用成熟库），先取那个组件的文档。
5. 披露：第一、二、三层各放什么；功能清单每一行落在哪一层。
6. 因果：功能清单里每个动作一行「做了 → 画面怎么变」（layout.md §6）。

## 3. 做方案图（照 stageshow，它说了算）

- 从头到尾读 [stageshow](../methods/stageshow/SKILL.md) 和它的 `references/craft.md`，照它的 Workflow 1–7 步做；用到的 kit 部件读 `references/kit.md` 对应条目，取景照 `references/framing.md`，动画照 `references/motion.md`。它和项目写法不同时照它（[rules.md](rules.md)「裁定」）。
- 放在使用方项目的 `design/<这件事>/`（前端在 `web/` 下就放 `web/design/<这件事>/`），把 `../methods/stageshow/kit/` 整个拷进去成 `design/<这件事>/kit/`，从项目自己的开发服务器开一个入口页给用户看。方案图不进产品路由，不被产品代码引用。
- 外观：舞台里直接用项目的 HeroUI 组件和样式入口（含 heroui-theme.css；深色给 `theme="dark"`）。舞台里看得见的按钮、输入框、表格行、标签用项目已装的组件（stageshow `references/looks.md` 里「用开发者自己的组件」那一段），窗口、手机、光标、动效部件用 kit 的；数据写死，不连真接口。
- 一份方案：主任务那一屏做一段有因果的动画（3–5 拍 + 结果停住，封面帧就是结果），拍子照 2.5 的因果表；别的页各一张静图，最后一张「要你拍板」表（三列：问题、推荐、另一种）。结构照 2.5 选中的骨架，画面只出现功能清单里的东西。
- 排练照 stageshow `references/rehearse.md`：`film.mjs` 在 `../methods/stageshow/scripts/`（第一次在那个目录 `npm install`），展示宽度和 358 宽各拍一遍，`--gate` 到 `rehearsal passed`；`REHEARSAL.md` 写在方案图旁边。

## 4. 评审方案图（过了才写真页面）

方案图（展示宽度、358 宽）和 3 张先例并排，逐条答「是」：
1. 分区、主动作位置、筛选贴着谁、数据怎么排、详情怎么打开，和共性一致；共性和 layout.md §1 名单、§4、§6 不同时照 layout.md（它来自盲评，排在先例前面；先例常把新增做成表单，11-07 第二轮就这样被带偏过）。
2. 一屏一件事；标题是名词、和当前导航项一致、不复述按钮。
3. 控件挨着它作用的对象；同类控件挨在一起、同一种外形。
4. 并排的一组项结构相同。
5. 画面里每一块都对得上 2.5 区域表里的一个组件（HeroUI 没有的写明怎么拼、用哪个库）；新增、详情、行内改值、切范围的形态逐条对过 layout.md §4、§6。
6. stageshow 自己的关：`references/teaching.md` 的整体构图与风格两组问题都答「是」，`references/review.md` 的新眼睛审过。
7. 358 宽下顺序和可用性仍成立。
8. 第一层有这件事的形状（不是只有数）；同一份数据只画一次。
9. 2.5 因果表的每一行，动画里演到了或静图里标出了；没有「先空再跳」「只淡入」「弹 toast 复述」。
10. layout.md §8 的坑一条都没有。

评审人：另起一个没参与的智能体，只给它总纲 DESIGN.md、先例图、拆解、2.5 的六样、方案图截图和这张表；没有子智能体就自己逐条答并写进汇报。没过就改方案图重审。

评审通过就停：只要方案的，打开方案页给用户看，附 3 张先例、评审结论和「要你拍板」表；要做完的，接着照 [build.md](build.md) 写真页面。
