# 布局手册：姿态 → 三版骨架 → 形状 → 组件 → 披露 → 因果

设计总纲（[DESIGN.md](../DESIGN.md)）§3–§5 的做法细则，合格线照总纲 §2。组件名写 HeroUI 的（[rules.md](rules.md) 边界 4）；换了组件库，布局照样成立。

用户 2026-11-06：「目前最大的问题是布局」「你得先给我一个 70 分甚至 80 分的布局与交互」「1. 总是想把所有东西都挤在一起 2. 组件永远只用那一两个，高级点的组件完全不用 3. 动画不加，交互缺乏连续性和前后因果逻辑……也不做渐进式披露」「不能每次一看侧边栏就把所有东西全塞进去，千篇一律，毫无想法」「那种可以被量化的设计的感觉，你一定是需要着重注意的」。
依据：同一题 7 种做法的盲评（本插件仓库 `evals/2026-11-06-技能盲评/`）。7 份骨架几乎一样，分数差在四处：进度画没画成形状、详情挡不挡名单、新增走不走表单、切换和改值有没有过渡。下面每条都来自两位评审一致的扣分或加分。第二轮（11-07，换一题、两份都用 HeroUI）：AI 评审给照本手册做的那份 75 分，**用户给 40 分**（乱、没主线；列距不统一；不翻页；新增一塌糊涂，见总纲 §2）。所以标「盲评」「11-07」的条目只是 AI 评审的意见，和总纲、用户档案冲突时照总纲；用户点名的四处已改进本手册（标「用户 11-07」）。

## 1. 定姿态

| 姿态 | 人在做什么 | 第一层只放 | 骨架 |
| --- | --- | --- | --- |
| 总览 | 扫一眼、找落后的、点进去 | 每块的状态形状（进度、数、趋势），整块可点 | 网格或分组列表；不放明细表 |
| 名单 | 找一条、改一两个值、看详情 | 范围、搜索、名单（表头吸顶、首列不截断、列宽按内容、一屏放不下就翻页）、行内改值 | 范围切换 + 表格 + 翻页 + 不挡名单的详情 |
| 队列 | 一条条读完再判 | 消息行列表 + 阅读区，动作钉底、建议的一步实心 | 两栏（用户 2026-11-06 否了卡片流） |
| 编辑 | 改一份东西 | 正文或画布；属性在旁 | 主区 + 属性栏 |
| 设置 | 偶尔改 | 分组的字段，改了即生效 | 一列，限宽 |

一屏只有一种姿态。需求里混了两种（看总进度 + 管名单），就让总览成为名单的一个范围（「全部」），不并排塞两块。

名单（11-07，两位评审都从对照组里挑出来要借的）：
- 默认按最要紧排：有截止日就按下一个截止日升序，逾期自然在顶；详情里的子项也是没做完、截止早的在前，做完的沉底。
- 一个范围的意思是「待处理的事」（逾期、待审核）时，名单的一行就是那件事（一行一项权益，带上它属于谁），行尾就地处理；不是把对象再列一遍。
- 范围已经说明了的列去掉（进了「金牌」就不再有套餐列）；不放常驻的「共 28 家」计数行。

## 2. 出三版骨架，挑一版

写方案图之前，各用一行写：

- **A 先例版**：照 Mobbin 的共性排。
- **B 形状版**：把这件事独有的数据画成形状放进第一层（§3）。盲评里只有两份想出了形状（「计划几位就画几个座位」「席位条」），两位评审都把它们列为布局或交互最好。
- **C 少一层版**：删一个区或合并两个区（范围只在侧栏出现一次、页头不再复述；详情不分标签页，往下排）。

按顺序挑：第一眼看得出最重要的东西和下一步 → 主任务步数最少 → 不挤（§7 预算）。写成「选 B，因为……；从 A 借了……，从 C 借了……」。没有三行，不开始方案图。

## 3. 数据 → 形状（第一层用形状，不用一串数）

| 数据 | 画成 | 不要 |
| --- | --- | --- |
| 完成几个 / 计划几个 | 每个范围、每一行都是库里的细进度条 + `3 / 6 项`（带单位，只占一行高）；位子有名有姓、点得开、不超过 12 个（嘉宾席位）才画「座位」：计划几个画几格，确认的实心、推进中的半色、空位虚线，每格 ≥ 16px，格上写人名、点名开详情 | 只有数字；同一份进度在侧栏、页头、名单里画两三遍；12px 的自画点阵（空位淡到看不见，11-07） |
| 流程走到哪 | 横向步骤条，节点可点：未开始灰、进行中黄、完成绿，连线随进度长 | 一行「第 3 步」；纯文字标签 |
| 枚举状态 | 彩点 + 字；要改就点它出菜单，`⌄` 只在指向时出现 | 每行常显 `⌄`；灰底胶囊；淡彩底块 |
| 时间里发生的事 | 时间线，新的在上；新记的一条插入、其余让位 | 表格；只显示最近一条 |
| 趋势 | 折线或迷你图 | 一排数字配箭头 |
| 份额 | 环形或堆叠条，图例贴着图 | 饼图 + 远处的图例 |
| 日期（截止、提醒） | 近的写相对（`逾期 6 天`、`还剩 7 天`），远的写日期；整个是按钮，点开日期选择器（11-07） | 原生日期框（盲评致命项）；只写日期让人自己算 |

## 4. 区域 → 组件

先读组件的文档再写：`node <本技能目录>/methods/heroui-react/scripts/get_component_docs.mjs <组件名>`。HeroUI 没有的件照 [connect.md](connect.md) 拼或用成熟库。

| 区域 | 用什么 |
| --- | --- |
| 侧栏、窄屏抽屉导航 | `ListBox`（单选）加页面布局拼（[connect.md](connect.md)） |
| 范围 ≤ 7 个 | 侧栏导航项：名字 + 细进度（`ProgressBar size="sm"`）；窄屏换成页顶一排能横滑的 `Tabs`，进度跟着走，不收进下拉（下拉里看不见进度，11-07） |
| 范围 > 7 个 | 页头 `ComboBox` / `Autocomplete`（能搜） |
| 页头 | 范围名（大）+ 一句摘要（`已确认 12 / 40`）+ 一个主动作 `Button variant="primary"` |
| 找一条 | `SearchField`，贴着它管的名单 |
| 名单 | `Table` + `Table.ScrollContainer`，表头单元格与首列单元格加 `sticky`（盲评实测可用）。列宽按内容：每列写死到放得下最长的值，最后补一个不写宽度的空列吃掉多出来的宽度，别让第一列或哪一列自己撑大（用户 11-07：相邻列距 181 / 52 / 46 / 62 / 172px 被说「离得这么远」）。一屏放不下就在 `Table.Footer` 放 `Pagination`，总数写在 `Pagination.Summary`（HeroUI 文档的表格翻页写法；用户 11-07） |
| 行内改状态 | `Select` 或 `Dropdown`（触发器静止只显彩点 + 字） |
| 详情（宽屏） | 不挡名单的浮层：`Surface` + 阴影，靠右浮在名单上，用 `motion/react` 滑入；HeroUI 的 `Drawer` 是模态的，宽屏不用；不用宽度动画把名单推窄（逐帧重排、末列被截，11-07） |
| 详情（窄屏） | `Drawer` 从底部出 |
| 新增 | 表尾一行「新增」（`Table.Footer` 里、翻页条上面，或表格最后一行）：点了就地变成一行输入，只填名字和决定后面内容的一两格（`TextField` + `Select`，范围预填），回车建好、Esc 放弃；建好后这一行按排序落到该在的位置并亮一下，次要字段点开详情再补。不开面板、不弹 `Modal`；建好之前不算进总数、不标逾期、不出现催办和下一家（档案 §3.3；用户 11-07：「新增展商这边做的一塌糊涂」） |
| 记一条 | 时间线顶上一个输入框，写了字才露出日期（`DatePicker`）、方式（`ToggleButtonGroup`）、记下 |
| 一排指标 | `Surface` 里放数 + 趋势；同一排同形 |
| 图表、命令面板 | 成熟开源库，交付时写明用了哪个 |
| 时间线、步骤条 | HeroUI 没有：用库里的零件拼（按钮、进度条、分隔线），不是从 `div` 造一个库里已有的控件 |
| 空、加载 | 空：一句事实，有下一步就配一个 `Button`（HeroUI 没有空状态组件）；加载：`Skeleton` |

## 5. 披露阶梯

- 第一层（静止就在）：这一屏的名字、当前范围、第 3 节的形状、名单的主列、一个主动作。
- 第二层（指向、选中、聚焦才出现）：行操作、`⌄`、复制、截断字段的全文、输入框的附加项。
- 第三层（点开）：详情、编辑、历史。不超过三层。
- 功能清单里每件事都能在某一层找到；能在第二层办完的不进第三层。
- 同一个对象的几块信息，面板够高就往下排，不用标签页藏起来；标签页只给真正互斥的视图。

## 6. 因果：每个动作画面怎么变（写真页面时一起做）

| 用户做了 | 画面怎么变 | 盲评扣分的反例 |
| --- | --- | --- |
| 切范围 | 旧的先退、新的再进（`AnimatePresence mode="wait"`，退场 ≤ 120ms），或按方向滑 8–16px；旧行不先消失成空白，高度不跳；进度、计数过渡到新值 | 先空一下再跳（4 / 7 份）；新旧叠成残影（11-07） |
| 行内改值 | 原位换字（上下滑），颜色同时换，牵连的形状（座位、进度）一起变；能撤销就把撤销留在原位（字旁或行尾） | 弹 toast 复述（4 / 7 份） |
| 新增 | 表尾那一行原地展开成输入，焦点在名字；回车后这一行滑到它按排序该在的位置（`layout`），其余行让位，落定亮一下 | 弹表单对话框；开一个盖住名单的大面板（用户 11-07 打 40 分） |
| 开详情 | 面板从它停靠的一边滑入（不只是淡入），选中行保持高亮，名单还能点 | 模糊遮罩糊掉名单 |
| 上一位 / 下一位 | 面板不动，内容换；按钮钉在面板底部、位置不变 | 面板关了重开 |
| 记一条 | 新条目插到时间线顶上，下面让位 | 整段重渲染、跳 |
| 删除 | 原位收起，给撤销 | 二次确认弹窗 |

- 动画只用库写明的机制：HeroUI 自带的进出场，加 `motion/react`（`AnimatePresence`、`layout`）做插入、让位、滑入。细则见 [motion.md](motion.md)。
- 键盘触发的不做动画；减少动态时只留透明度。

## 7. 量化预算（1440 首屏；`scripts/probe.mjs` 量）

| 项 | 预算 | 来由 |
| --- | --- | --- |
| 字号 | ≤ 4 种 | 7 份都在 3–4 |
| 实心强调按钮 | 每个区域 ≤ 1，整屏 ≤ 2 | 7 份都是 1 |
| 常驻控件（重复行只数一行） | ≤ 15 | 最高两份 13、14；超 20 的两份被评「挤」 |
| 文字与控件盖住的面积 | 35%–55%；名单铺满首屏的表格页不量这一条（探针不算表格行和自画形状），改看名单是否铺到首屏底 | 最低两份 27%、33%，评审都说下半屏空、太素 |
| 关键字被截断 | 0 | 首列截断人名，3 份被扣 |
| 390 宽横向溢出 | 无 | — |
| 表格相邻两列内容之间的空白 | 最宽和最窄差 ≤ 16px | 用户 11-07：181 / 52 / 46 / 62 / 172px 是「离得这么远」 |
| 名单排到首屏以下 | 有翻页条 | 用户 11-07：「没有考虑到翻页的情况」 |
| 交互途中帧 | `shoot.mjs` 报「点后 400ms 画了几帧」：≥ 3 帧才算有过渡；90ms 那张（录屏帧）和点之前、停稳后都不同，不是「屏幕还没变」，途中没有空白名单、新旧叠影 | 切范围下沉、空行、残影 |

超出不是死规定，但要写出理由（这一屏为什么要多）。

## 8. 交付前逐条查（盲评里扣分最多的）

用户 11-07 点名的先过：页面没有一条主线（最急的没排在一起）· 列距不统一、第一列吃掉多余宽度 · 长名单不翻页 · 新增开大面板、没保存、新建时摆出催办和下一家。

原生日期框 · 灰底控件和灰底胶囊 · toast 复述看得见的结果 · 同一份进度画两遍 · 首列截断人名 · 改动状态列的位置（照原表顺序） · 每行常显 `⌄` 或同一个图标 · 提示里印键帽 · 淡彩底块当装饰 · 模态遮罩挡住还要点的名单 · 有空间却用标签页藏信息 · 新增弹表单 · 切换先空再跳 · 详情只淡入 · 新旧叠影 · 宽度动画推窄名单 · 草稿算进总数 · 同一列输入框右缘不齐 · 名单默认不按最要紧排 · 常驻计数行 · 灰圆底关闭钮 · 12px 自画点阵。
