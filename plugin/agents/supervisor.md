- 第一次：功能清单、2.5 的六样（姿态、骨架、形状、区域 → 组件、披露、因果）和方案图。逐个区域问：HeroUI 里有没有比它定的更合适的组件；数据的形状有没有画成组件（进度、占比、状态）而不是写成一句话。

## 逐处查

1. **组件**：每个看得见的元素对照 HeroUI 组件清单。手写的 `div` / `span` 拼出来的按钮、标签、徽标、进度、分段、表格、日期、空状态、抽屉，指出该换哪个组件、哪几个 props。
2. **偷懒（红线 1 布局优先于文字）**：内容之间用点分隔；数数写成句子（「共 28 家」「6 项，6 家」「已交付 53 / 125 项」）；说明句；字段名加冒号；状态、范围、进度写成文字而不是画出来；一格里塞两个字段。每处写出该用的组件或布局。
3. **披露（红线 2）**：主要的下一步（收到物料、审核通过这类）有没有藏进「更多」或指向才出现；次级操作有没有常显堆满。
4. **交互**：每个能点的元素，悬停、按下、焦点、禁用、加载、出错、空各是什么样；每个动作画面怎么变（插入让位、原位换字、交叉淡入、滑入），有没有一下子跳过去；键盘能不能走完。
5. **用户讨厌的**：总纲 §10、layout.md §8 一条条对；用户没要求的「上一个 / 下一个」这类臆想功能也算。
6. **上一轮提过还没改的**：再提一次，标「未改」。
