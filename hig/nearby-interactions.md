# 附近交互

原文：https://developer.apple.com/cn/design/human-interface-guidelines/nearby-interactions

附近交互支持设备端使用体验整合附近环境中存在的人和物。

![](https://developer.apple.com/tutorials/images/com.apple.HIG/inputs-nearby-interactions-intro@2x.png)

良好的附近交互对用户而言是直观且自然的，因为它建立在用户对周围世界的固有意识之上。例如，将设备彼此靠近时，用户可以在 HomePod mini 上继续欣赏 iPhone 上播放的音乐，只需将音频输出从 iPhone 转移到 HomePod mini 即可。

附近交互在支持超宽带技术（若要进一步了解，请参阅[超宽带技术提供情况](https://support.apple.com/en-us/HT212274)）的设备上可用，并依赖于 [Nearby Interaction](https://developer.apple.com/cn/documentation/nearbyinteraction) 框架。在参与附近交互体验前，用户会授权设备在使用 App 时进行交互。接近互动 API 依赖随机生成的设备标识符来帮助你保护用户的隐私，此类标识符只在 App 发起交互会话期间有效。

## 最佳实践

**任务应考虑从物理世界的角度来寻求附近交互的灵感**。例如，虽然用户可以轻松地使用 App 的用户界面将歌曲从 iPhone 转移到 HomePod mini，但通过将设备彼此靠近来启动转移能给人一种任务扎根于物理世界的感觉。发现传达任务概念的物理操作可帮助你打造有吸引力的使用体验，使得执行任务感觉轻松且自然。

**使用距离、方向和环境来传达交互**。虽然 App 可以从各种来源获取信息，但优先考虑附近的环境关联信息可帮助你提供感觉自然的使用体验。例如，如果用户想在一个拥挤的房间里与朋友共享内容，iOS 共享表单可以通过使用设备端关于该用户的最常联系人和最近联系人信息来建议可能的收件人。将此类信息与来自内置 U1 芯片的附近设备的信息相结合，可让共享表单通过建议用户面前的距离最近联系人来改善使用体验。

**考虑物理距离的变化可以如何引导附近交互**。在物理世界中，用户通常期望自己越接近一个物体，对它的感知就越敏锐。附近交互可以通过提供随物体接近程度而变化的反馈来反映这种体验。例如，当用户使用 iPhone 查找 AirTag 时，显示会随着二者距离的缩短从方向箭头转变为跳动的圆圈。

**提供持续的反馈**。持续的反馈反映了物理世界的动态性，并加强了附近交互和用户所执行任务之间的联系。例如，在“查找”中寻找丢失的物品时，用户可以通过持续的更新来了解物品的方向和接近程度。通过提供响应用户移动的不间断反馈来保持他们的参与度。

**考虑使用多种反馈类型来打造整体体验**。视觉、听觉和触感反馈之间的流畅过渡可让附近交互的任务更具参与感和真实感。使用多种类型的反馈还能使体验多样化，以协调任务和当前环境。例如，当用户与设备屏幕交互时，提供视觉反馈较为合理；而当用户与所在环境交互时，听觉和触感反馈通常效果更好。

**避免将附近交互用作执行任务的唯一方式**。你不能假设所有用户都能体验附近交互，因此你必须在 App 中提供完成任务的备选方法。

## 设备使用情况

**鼓励用户以竖排方向握持设备**。以横排方向握持设备会降低其他设备的距离和相对方向信息的准确性和可用性。若附近交互功能运行时只支持竖排方向，最好向用户提供隐式的视觉反馈，告诉他们如何握持设备才能获得最佳体验；应尽量避免明确地告诉用户要以竖排方向握持设备。

**基于设备的方向视场而设计**。附近交互依赖于具有特定视场的硬件传感器，与 iPhone 11 及后续机型中的超广角相机类似。如果参与设备在这个视场之外，你的 App 可能会收到它的距离信息，但不是它的相对方向。

**帮助用户理解干扰对象会如何影响 App 中的附近交互体验**。当其他用户、动物或足够大的物体出现在两部参与设备之间时，距离和方向信息的准确性或可用性可能会降低。考虑在你呈现的用户引导或教程内容中加入避免此类情况的建议。

## 平台考量因素

*无针对 iPadOS 的额外考量因素。在 macOS、Apple tvOS 或 visionOS 中不受支持。*

### iOS

在 iPhone 上，接近互动 API 提供了对等设备的距离和方向。

### watchOS

在 Apple Watch 上，接近互动 API 提供了对等设备的距离。此外，所有参与附近交互体验的 watchOS App 必须在前台运行。
