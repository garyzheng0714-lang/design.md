## 和 AI 合作做界面的方式（回复长短、问不问、先给什么、怎么改）

- 先出可体验的 HTML 演示，不碰正式代码；演示要覆盖完整流程和多个场景（上传后、规则后台）：「1. 先不要改正式代码，先给我一个 HTML 演示。2. 在这个 HTML 里要能体现整个交互流程，让我可以体验不同的场景（比如上传文档之后的效果）。」（2026-05-30）；「还是不够细化。」「我需要看到更多的场景，比如说规则后台。」（2026-05-30）；「优化给我看看，先别改代码。」（2026-06-03）；「我希望你可以用人话跟我解释一下，最好画出html，我来仔细看看。」（2026-07-10）
- 改之前先查原因、先给方案确认：「可以先查一下是什么原因。然后再改，先查明。」（2026-05-19）；「这是两个问题，先别着急改，现在先找原因。」（2026-06-04）；「推送完之后，你给我2个方案。」（2026-05-27）；「可以先跟我确认一下方案。」（2026-06-02）；「解决这些问题，解决前线列出详细的方案跟我确认。」（2026-07-16）
- 说人话、直接回答：「我需要你非常直观、清楚地告诉我：1. 旧版本为什么不兼容？2. 到底缺的是什么东西？3. 我该怎么去替换？4. 替换成什么模块？」「反倒是在这里跟我说七说八，这也不行那也做不了。」（2026-06-07）
- 问与不问的分界：明显的界面 bug 不许问，自己去看（见「最烦」第 1 条）；需求和交互结构没想清时，TA 主动要被追问、欢迎反驳：「用AskUserQuestion工具向我反复提问」（2026-06-05）；「以上是我的构思，你完完全全可以反驳我并提出更完美的方案，我十分信任你，让我们一起把这个东西做好。」（2026-07-10）
- 经常要「打开给我看」：「打开个本地预览我看看」（2026-05-25）；「打开页面我看看」「打开个预览我看看。」（2026-05-30）
- 分阶段交付时，要主动接上下一阶段：「我的阶段二在哪里」（2026-05-30）。
- 改得好、用户点头后要尽快上线：「先把你的这个粘贴自动排版的推送赶快推上去，我说了几遍了，你每次都不推呢？我都说我急着用了。」（2026-08-06）
- 被骂时不要只写记忆当交代：「傻逼东西，别老是写到记忆里。」（2026-05-29）
- 设计规范的源头：06-24 这次「输入框结合」的体验让 TA 要求建立个人设计准则：「不错。任何涉及到前端的UI，UX的，都必须经过design.md」（2026-06-24）。

## 拿不准的（信号弱或可能是特定项目的需求，不该推广成通则的）

- 层级「平台 > 账号 > 板块（作者）」、「第一层应该是发布渠道」：这是该排版业务的结构（「平台，账号，板块（作者），他们应该是这样的层级关系。」2026-07-11），可推广的只有「选择器层级照用户的业务结构排」。
- 公众号文章本身的排版数值：「更多文章」图不加文字阴影、NotoSansHans-Bold、表格边框「#544545」、作者名蓝色 RGB 84,124,175、底部二维码别太大：都是 FBIF 公众号的内容排版规范，不是界面规范。
- 「标题的第二行，不以标点符号打头」出自用户转贴的同事聊天，不是用户自己的话。
- 「这部分内容不要」「这部分内容也不要」（2026-06-03）：看不到图，不知指什么。
- 「我觉得得有一个二级页面才对。」（2026-07-25）：上下文不清，只知道 TA 觉得某流程该放到二级页。
- 「前端好像按钮还是灰色？」（2026-05-28）：可能是功能没开放而不是视觉问题。
- 导入 Stitch、按某个 Claude 设计稿做（2026-06-03、2026-08-02）：是当时选的工具，不是固定偏好。
