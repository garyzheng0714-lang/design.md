## 旧 §0 底层逻辑：九条原则（已由内核 K1–K7 取代）

用户 2026-09-25：「我们要的是它最底层的东西——哪怕换一套组件，依旧能搭出一个完美的画面，靠的是底层逻辑和原则。」

本节讲**怎么组合**，**长什么颜色、用什么字**见 §1。本节不依赖任何具体组件，每条都能在任意界面上检验。依据是官方产品截图 249 张的三份研究（页面布局、文档排版、组件组合，见研究资料 `docs/研究/`；下面的编号是截图序号）和用户定稿的条款更新弹窗。

**起点是用户任务。** 界面把业务关系变成能看懂、能操作的关系。颜色、尺寸和动效只能表达已经成立的关系；关系错了，换外观仍然会错。

**用法：做任何一屏，按这个顺序做决定**：

| 决定 | 开工前说清楚 | 验证时看什么 |
| --- | --- | --- |
| 任务 | 谁在什么情境下，对什么对象做什么；怎样算完成 | 默认入口是否直接走向完成 |
| 关系 | 哪个是默认、哪个是备用；谁包含谁；动作作用于什么；时间是记录属性还是事件顺序 | 用户能否从位置和操作读出同样的关系 |
| 状态 | 默认、展开、输入、处理中、失败之间怎么走；什么在变化中必须保持 | 焦点、当前分支、主动作和阅读位置是否仍能追踪 |
| 布局 | 关系各自落在哪条内容线、哪个容器和哪块热区 | 内容变长、换宽度、滚动和折叠后关系仍成立 |
| 外观 | 用现有材质、刻度和频率档表达以上决定 | 浅深色、指针与键盘行为一致 |

九条原则用于检查这些决定，模板是已验证的常见组合。不要从「放几个按钮」「套哪张卡片」开始。默认通道由业务决定；设计系统负责让主次清楚，不替所有产品指定同一种登录方式。

### 0.1 一块内容区，一个主角

- **原则**：页面是一块中性纸底。层级靠位置、留白和明度差；白色只表达浮起的小面。一个视图最多三层。
- **做法**：侧栏与页面明度只差 1–2%；内容直接落在 canvas，不画大白卡与卡边。Card / Surface 页级默认透明；弹层内的小面、输入卡与浮动工具用白底柔影。
- **检验**：侧栏和内容仍能靠位置识别；页面大面计算底色为 canvas，无卡影。除表格行和分节线外，分隔线为 0。
- **证据**：036、124、089——内容区离窗框上、右、下都是 6，左边贴着侧栏。
- **反例**：灰底上叠一张覆盖整页的大白卡；只为分区再套卡片。

### 0.2 一个重心，主动作在中轴

- **原则**：每一屏只有一个视觉重心，它就是用户下一步要做的事；首要的输入放在中轴上，不放在角落。
- **做法**：首页和空状态 = 居中的标识 + 一张大输入卡（约内容区宽的 84%，整组略高于几何中心）；对话 = 居中的正文列 + 底部浮起的输入框；对话框 = 左上粗体标题 + 右下唯一的文字色按钮，对角平衡。
- **检验**：眯眼看只有一处最重；主输入框的中线和内容区的中线重合。
- **证据**：036（命令卡 652 / 内容区 775，整组中线比几何中线高约 18）、124、条款弹窗。
- **反例**：首页是一棵页面树或一张列表，入口是左上角侧栏里的一行「搜索」。

### 0.3 主从，而不是并列

- **原则**：次要的东西依附在主要的东西上——从它长出来、贴着它、对齐它；不把屏幕切成几块同级的栏。
- **做法**：浮层离来源 4–10，对齐来源的一条边或中线（悬停卡和被悬停的行垂直居中）；行内编辑框出现在选区正下方，左缘对齐正文；打开侧面板时，原内容降一级成内容区里的一张卡，新面板直接写在内容区上。
- **检验**：任何浮层都说得出来源，并有一条边或中线和来源对齐；分屏后各块不在同一层。
- **证据**：068、069（悬停卡中线 361 / 行中线 360）、022（编辑框左缘 = 正文左缘）、035（窗口底色 → 内容区 → 网页卡片，三级各内缩 6）。
- **反例**：三栏同级并列、竖线分隔；菜单和预览固定在屏幕某处。

### 0.4 少而大

- **原则**：元素少，每一个都更大、更松。层级靠字重和浓淡，不靠更多字号、更多图标、更多分区。
- **做法**：界面字和正文字几乎一样大（差一档以内），按钮字 = 正文字；一个容器最多三档字号、两种浓度；侧栏只在业务分组影响查找时用 `NavSection` 标签，可展开的包含关系用 `NavFolder`；动作是少数带文字的平块，不是一排图标。
- **检验**：一屏里的字号种类 ≤ 4；没有只为排版而添加的分组名；工具栏里纯图标按钮 ≤ 4。
- **证据**：条款弹窗（标题 17、正文 16、按钮 16）；036 侧栏没有小标题，分区靠方块和一条线；028 右上是带字的 Share / Chat 平块。
- **反例**：把不同业务关系都画成同一种小标题；用一排图标代替用户需要辨认的动作。

### 0.5 一切由比例生成

- **原则**：只定少数几个比例，尺寸全部从它们推出来；换了字号，整套界面跟着重新生成，比例不变。
- **做法**：控件用组件的尺寸档，容器间距由宽度生成（§3.0），嵌套圆角由外角与间距生成。文本输入的行数上限用实际行高与内边距计算；文字换行、字体或容器宽度改变后重新量，不抄另一处的像素值。
- **检验**：改控件尺寸、文字长度和容器宽度，组合仍保持对齐、同心与间距关系；数值来自 §9 对应的源码真源。
- **证据**：037（按钮 36 配边距 20）、条款弹窗（按钮 40 配边距 28）、036（全窗 6 的网格）、文档页（刊头 → 标题 2L、导语 → 证据 1L）。
- **反例**：照一张像素表填值（24 / 28 / 32、4 / 8 / 12），换一个字号就散架。

### 0.6 对齐的是字，不是盒子

> **已废止**：本节「`NavFolder` 的展开箭头常驻」（内核定稿 §5.2）。现行：只有打开的组在行尾显示箭头，见 `docs/网站外框.md` 4.1 g。

- **原则**：人眼读的是字和图形，所以对齐线穿过文字和图标，而不是穿过容器的边。
- **做法**：容器向外撑出自己的内边距，让框里的字和框外的字在同一条线上；一张卡片里只有两条竖线（图标线、文字线），输入行、结果行、底栏按钮都落在上面；子项图标的中心对准父标题的起点；角落里的控件离两条邻边一样远。
- **检验**：画出每张卡片的竖线，文字起点只有 1–2 个 x 值，偏差 ≤ 1。
- **正文列组合**：同列的标题、可复制正文和表格首列共用左内容线；可复制块用同一外壳，外扩量与内边距同值、复制按钮同位。正文表格用 `Table flush`，不再叠首尾缩进（用户 2026-09-29：安装页三种缩进、两个复制块错位）。
- **包含与作用关系**：`NavFolder` 的展开箭头常驻，整行控制同一子组；父子文字共用内容线，折叠时父行保留当前分支。`Composer` 的输入和操作共享容器；输入长成多行后操作对齐最后一行，发送与停止共用一个位置。关系由原件保证，页面传业务状态，不逐页补偏移。
- **菜单与侧栏列表**：同一个菜单里图标全有或全无。`SplitButton` 给没图标的项补 18 的图标位。侧栏里的可选列表行字与小标题同线，行底向外撑出按钮内边距。
- **证据**：124（输入框比正文列两边各宽 28，框里的字和正文几乎同线）、036 / 097（图标线离卡片边 22、文字线 48）、068。
- **反例**：所有块都收进同一个列宽，框里的字因此比正文缩进一截。

### 0.7 结论先行

- **原则**：内容按「先给结论，再给证据，最后展开」排；只读前三行也不吃亏。
- **做法**：刊头（类别 · 日期）→ 大标题（按意思断行、行距收紧）→ 导语（第一句文字色，其余次级灰）→ 紧贴的证据（关键数字）→ 整页最大的留白 → 分节。证据离结论 1L，留白放在证据之后。
- **检验**：只读标题和导语第一句，能说出这一页的结论；关键数字离导语比离下一节近。
- **证据**：025、028、029、060。
- **反例**：标题下面先是一排属性（负责人、日期、状态），正文从背景讲起。

### 0.8 状态靠反差和材质

- **原则**：选中与当前在原底上同色加深；悬停永远比当前轻一档。凸起只给凹槽轨道里的滑块、键帽和圆钮。
- **做法**：当前项用实色灰填充，浅色 #e9e7e7 / 深色 #262626，无凸影；悬停叠黑 4%。主按钮文字色实底，次按钮白底 1px 中性线，第三级才用浅灰块。
- **检验**：把截图转成灰度，所有状态仍然分得清。
- **证据**：2026-10-05 截图取色与浅深色计算色检查；028（数字线框：外框 60%、格线 10%）。
- **反例**：选中用彩色底加左侧竖条；每个次要按钮都凸起描边。

### 0.9 界面退后，内容向前

- **原则**：界面靠位置、字号、留白与状态退后，文字始终清楚；不用灰字削弱可操作入口。
- **做法**：导航、列表标题、菜单、标签页与普通按钮用文字色、500；侧栏条目统一文字色，当前项靠底色。次级灰只给时间、计数、说明、分组名与占位符。
- **例外：本页目录**（页内锚点、「查看 Markdown」「回到顶部」）是辅助导航，退到正文后面：14 / 400 次级灰，当前节与悬停只换成文字色；不加底色块、不改字重、不画竖条。主导航那套「文字色 500 + 底色」不能搬到目录上（2026-10-05 用户：全黑加粗、当前项套灰块「恶心」）。
- **检验**：主导航默认与当前项的文字色、字重相同；本页目录非当前项为次级灰 400、当前项为文字色且无底色；信息灰为实色，基础面与选中底对比度 ≥4.5:1。
- **证据**：028、094、124（地址栏「应用名 / 页面标题」一深一浅）。
- **反例**：用文字透明度、细字重或黑灰渐变制造层级；导航未选时发灰。

**不学的**：主题色的窗口底色、彩色对话气泡、整页淡彩底、彩色分组与托盘（用户 2026-09-25 明确不要）。这些原则全部用本系统的颜色实现。

## 旧 §1 视觉：材质、颜色、字体与光影（已由 `DESIGN.md` §4.1、§4.3 取代）

本节只管**东西长什么样**：材质、颜色、文字色比例、字体、圆角与光影。其中关于布局的条目（4 固定宽度、5 对齐线）以 §0 为准；具体数值在 §9。

### 1.0 视觉语法：六种状态（每个元素只能是其中一种）

| 状态 | 含义 | 外观 | 用在 |
| --- | --- | --- | --- |
| 平 | 可以读 | 直接写在 `bg-canvas`（页面）或 `bg-sidebar`（侧栏）上，无底色、无边框 | 文字、列表、导航、表格、手风琴、页面内容 |
| 凸起 | 可以按 | `bg-card shadow-raised`；按下 `shadow-pressed`（压平） | 键帽、滑块圆钮、开关圆钮（次要按钮是平的浅灰块，不凸起） |
| 凹下 | 可以填 | `bg-well shadow-inset` | 输入框、选择器、复选框、滑轨、分段切换的凹槽。复选框、单选圆点这类 16px 的小控件（含 `RadioCards` 里的点），未选时内边界改用 1px `fg-subtle`（`shadow-[inset_0_0_0_1px_var(--ds-fg-subtle)]`），保证在白卡上非文字对比 ≥ 3:1（WCAG 1.4.11；2026-10-04，contrast-audit 查） |
| 当前 | 选定 | 当前项同色加深：`bg-selected / bg-nav-current`，浅色 #e9e7e7、深色 #262626；直接出现、不滑动、不改字重、无凸影。凹槽轨道里的 `variant="raised"` 保留白块沿轨道滑动 | 选中项、当前页、当前视图 |
| 浮 | 临时 | 输入卡与临时工具 `bg-card shadow-popover`；菜单 `bg-menu`、轻提示 `bg-notice`；对话框与抽屉 `bg-canvas shadow-overlay` | 输入卡、菜单、弹出层、对话框、抽屉、提示 |
| 折痕 | 分隔 | 1px `border-line` | 只在留白不够时：表格行、手风琴项 |

- 文字与图标三种浓度 `fg / fg-muted / fg-subtle`（实色中性灰）。主次靠浓淡和字重，不靠颜色；颜色只留在小面积上（圆点、图标、危险按钮）。
- **主题色只有一个变量 `--base-primary`**（浅色 `#1378fe`、深色 `#3b8dff`）：选择控件用它；链接、焦点环、未读点从它派生。主按钮读中性 ink，当前行读中性 selected，不铺品牌色大面。
- 光从正上方来：凹（可填、可拨）/ 平 / 凸（可按）/ 浮（当前项被拿起）/ 悬 / 罩；拟物只靠这一套光影和手感，不画纹理（§9.2「材质」）。
- 基调收敛、克制、常规：辅助入口、设置、开关和工具按钮不抢视觉中心；层级靠位置、分组、浓淡、悬停、提示和状态反馈表达，不靠夸张尺寸、重色块、大圆角、厚边框、强阴影、装饰性渐变和营销页式布局。做完和同屏元素比一比，突兀、过大、过重就收。

### 2.1 定律与落地（出处：Laws of UX、Refactoring UI、Apple HIG；数值对照 §9.1）

- **特斯勒定律**：复杂度只能转移，由系统承担，不交给用户。落地：自动填充、记住上次的选择、合理的默认值；能推断的不让用户填。
- **认知负荷**：不帮助理解的元素都在消耗注意力。落地：不用装饰性渐变、彩色底块、无意义图标；标签是灰色文字，颜色只留给状态。
- **从过多的留白开始、不必填满屏幕、网格被高估**：先给足空间再往回收；每个元素只拿它需要的宽度；侧栏、检查器、对话框定宽，只有主内容列吃剩余宽度（§3.2）。
- **共同区域、组块**：优先用留白分组，留白不够画一道 1px 折痕，不用卡片或灰底框一组；列表按日期或类别分组，长数字分段显示。
- **雅各布定律、心智模型、相似性**：搜索在顶部、导航在左、确认在右下；能按的凸起、能填的凹下、「关闭」就是放回原处；同一种状态全站一个样子，不可点的不长得像按钮。
- **改版要渐进**：已有入口就升级它，不新增同义入口；组件 API 沿用 shadcn 的命名。
- **心流、再认优于回忆**：J / K 连续处理，做完一件自动给出下一件；面包屑、筛选条件、当前位置始终可见；最重要的导航放最前，最终动作放最后。
- **波斯特尔法则**：接受空格、全角、大小写等不同写法；长文本截断并可看全文；用最长的真实内容测布局。
- **主动用户悖论**：没人先读说明书。空状态边用边教，不做强制导览；界面提示照 §9.8「提示三问」。
- **美学可用性、峰终定律**：好看靠对齐、同心圆角、一致的留白；完成时给一句清楚的确认，出错、空状态、404 都认真写，结束时不推销、不挽留。

### 2.2 刻意不做

- **人为延迟**：为了「显得认真」让用户等。快就是快。
- **红点与未完成感驱动**：用焦虑推动点击。只在真正需要处理时提示。
- **游戏化激励**：积分、连胜、庆祝动画不属于工作工具。完成就是最好的反馈。
- **为「少点击」堆功能**：把所有功能摆在首屏，省了点击，费了眼力。
- **强制新手导览**：一连串弹窗介绍功能。用户会跳过，而且打断了他们要做的事。

## 旧 §3 布局法

### 3.0 两条根：布局属于页面，间距属于容器（2026-09-28）

用户 2026-09-28：「我要的是道，不是术。用代码去做设计，而不是视觉。间距应该是容器和组件之间的间距，布局应该跟页面相关。布局决定页面观感，间距决定阅读体验。」

以前的数字是照着参考站一格一格量出来、再手填进每个区块的——换一个容器就不对，而且每个人填得不一样。现在只写结构，数字由代码算：

| 律 | 说法 | 代码里怎么落 | 审计 |
| --- | --- | --- | --- |
| 一 **间距属于容器** | 组件没有外边距；两样东西之间隔多远，由装着它们的容器决定 | 装东西的地方一律用 `Surface`（或 `Card`，二者同一套）；对话框、抽屉写 `data-inset` + 自己的宽度公式 | `space-audit`：带底色、圆角 ≥ 12 的面，内边距不是容器算出来的 → 报 |
| 二 **容器越大越松** | 内边距 = 8 + 宽 ÷ 24（取 4 的倍数，12–64）：8 跟着字，比例跟着容器——小卡不挤、大窗不空 | `data-space` 的元素是尺寸容器，`p-inset` 读它算出的值 | 同上：面的内边距 ≠ 它算出的 `--ds-inset` → 报 |
| 三 **越往里越紧** | 边 > 组与组 > 同组的项 > 一项里的部件（邻近原则写成不等式）：×1 · ×0.75 · ×0.4 · ×0.2 | 只写关系：`p-inset` `gap-group` `gap-item` `gap-part`，不写 `p-4` `gap-6` | 同上 |
| 四 **组件原尺寸** | 组件从不缩放；放不下就换行、换列、占满一行；只有「整页的缩略图」可以缩放 | 格子 `repeat(auto-fill, minmax(组件最小宽, 1fr))`；宽组件 `col-span-full` | 首页与区块里 `transform: scale` 只许出现在整页缩略图上 |
| 五 **布局属于页面** | 几列、正文多宽、段距多大，由页面此刻的宽度决定；区块只说自己要占多宽（宽 / 中 / 窄、几列），不写像素宽 | `Block` 的三档宽 + 容器查询；网格用 auto-fill 让页面自己排；「一行放几个」读网格实际排出的列数 | `layout-audit` |

推论：同一张卡放进窄栏自动变紧、放上大舞台自动变松；换了容器不用改一个数。下面十二律管「一段怎么排」，它们在这两条根之上。

`data-space` 的元素自己不写 `p-inset`，内边距写在它里面那一层。

### 3.0a 布局十二律（硬约束，2026-09-28）

用户 2026-09-28：「布局还是让人不够舒服，而且无法复制，某些好，某些又不太好。需要一个很严格的基础限制和 law，否则无法做到每次设计都让人惊艳。」

**好看来自「最常见的线框做到最准」**（2026-10-05 改，用户：「线框图里最常见的搭配你都做不好」「又复杂又不好懂」）：先照用户最熟悉的骨架排（首屏是标题 + 一句 + 按钮 + 产品画面；功能是标题 + 等宽网格或左右图文；价格是并排方案），再把字号、留白、对齐做准。破格不是每段必备：一页至多一处，多数段不需要。原来「每段一处破格」逼出了两翼散布、四角构图这类看不懂的花招，已废止。

复盘 54 个区块时，排得不舒服的几乎都是这几种毛病：一侧空出一大片（空洞）、标题居中而内容左对齐（两条轴）、块头每段长得不一样（字号、眉题、间距各异）、散落的小部件没有网格（乱）、卡片里套卡片（灰托盘里摆白卡）、一段里好几个同样重的东西（没有重心）。十二律逐条堵住它们。

落地方式：区块只用 `ui/block` 的四个原件拼（`Block` · `BlockHeader` · `BlockSplit` · `BlockGrid`），法则写死在原件里；`scripts/layout-audit.mjs` 量出来违反的逐条报出（第几律、差多少），输出为空才算过。「应用」类区块（整窗应用界面）不用 `Block`，照 §3.2 宽度阶梯与 §3.4 模板，但第 4、6、9、10、12 律同样适用。

原件的正当扩展：`Block innerClassName="pb-0"`（画面被段的下沿切断）、`innerClassName="grid"` + `[grid-area:1/1]`（名字居中、四周摆东西的首屏，把块头和另一层叠在同一格）；巨字本身就是标题时用 `h2` 标 `data-break`，不走块头。

**一段的生成顺序**（每步只做一个决定）：① 这段的重心是什么（律 4）→ ② 对齐轴：左还是中（律 2）→ ③ 宽度档与比例（律 1、7）→ ④ 块头（律 3）→ ⑤ 重心放进宽栏或正中，其余依附（律 4、6）→ ⑥ 默认不破格；整页真需要时才选一处（律 11）→ ⑦ 数字只从律 5 取 → ⑧ 跑 `layout-audit`。

### 3.1a 渐进式披露：三层（2026-09-28，用户：「让复杂性分层呈现」）

每一页只有三层，不再往下嵌套（研究 `docs/研究/渐进式披露.md`）：

| 层 | 怎么到达 | 放什么 | 上限 |
| --- | --- | --- | --- |
| 第一层 | 打开就看见 | 标题 + 至多一句 + 一个活的重心 | 主区可操作 ≤ 6（成组的控件按组计，示例内部不算）；字号 ≤ 4 档 |

### 3.2 宽度阶梯（固定值，不按百分比伸缩）

```
栏：  56 图标栏 · 228 应用侧栏 · 240 检查器 · 256 站点侧栏 · 300 宽检查器 · 368 列表栏 · 400 抽屉 / 工具侧栏 · 460 压缩列表
列：  320 单任务表单 · 460 对话框 · 480 表单 · 560 窄阅读 · 640 命令面板 · 672 正文 · 864 文档页（正文 672 + 两侧 96）
页：  1024 桌面断点 · 1344 宽版（画布/三栏） · 1600 上限
```

- 相邻两档至少差 15%（栏）或 25%（列），来自 L&S《建立间距和尺寸系统》。
- 文字列 ≤ 65 字符 ≈ 560–680（bbd-01 归纳 3、bbd-02 归纳 2）。容器再宽，文字列不变，多出的空间给留白或第二栏（L&S《不必填满整个屏幕》分栏思维）。
- 列表 → 详情不跳页：列表压缩到 `min(460px, 50vw)`，详情从右侧进入（bbd-00 站点本身）。
- 依据 L&S《网格被高估》：侧栏、检查器、对话框都是固定像素；只有主内容列 `flex-1`。

### 3.3 间距刻度与垂直节奏

- 装东西的面（卡片、面板、对话框、展示台）不填数：内边距和里面的间距由容器宽度算（§3.0）。其余间距只从刻度取（§9.2「间距」）。
- 阶梯即关系（LoUX 邻近、L&S《避免模糊不清的间距》）：元素内 4–8 → 同组 12–16 → 组间 24–32 → 区块 48–64 → 页段 96–128。组内严格小于组间。
- 垂直节奏：标题、正文按各自 token 的行高与语义间距排列，不在页面重写行高。侧栏项用 `--ds-h-row` 与 `--ds-gap-row`（36 + 4）；其余控件与列表尺寸见 §9.2。
- 留白从多往少收（L&S《从过多的留白开始》）：先用上一档，不够再降一档，不反向。

### 3.5 响应式：大件缩得多，小件不缩

- 缩小时字号只降标题（40→30、24→20），正文与控件不变（L&S《界面尺寸不该简单按比例调整》）。
- 触屏 `pointer: coarse`：控件 32/44/48，悬停规则不生效（rauno）。
- 手机宽度（390）下页面和每个示例都没有横向溢出：放不下就换行、换列、收起可收的栏；字不被挤成一字一行，数字不截断，标题末行不只剩一两个字（2026-10-04，`touch-audit` 查）。

### 3.6 对齐与居中的判定方法

1. **内容线**：每栏只有左右两条线。常在、看得见的东西（文字、图标线条、有底色/阴影的控件边缘）落在线上；透明内边距、悬停底色、图标自带留白不算。测量：`optical-audit` 取 SVG 路径包围盒 ± 线宽/2，与栏内容线差 ≤1.5px。
2. **字形边界**：文字与相邻元素的距离按大写高/基线算，不按行盒；支持时用 `text-box-trim: trim-both`（dd-00《CSS 文本框修剪》）。
3. **光学居中**：非对称图标在按钮里按模糊后的重心居中（dd-00《用模糊技巧…》）；带前置图标的按钮，图标侧内边距 = 文字侧 − 2（dd-03）。
4. **整体平衡**：固定宽列在可用空间里水平居中，左右留白差 ≤1px；展示物在展示台里居中，文字永远左对齐，同一列不混用。
5. **冲突时移动整个盒子**（用 `edge-start/edge-end`），不在盒子里挪内容——否则悬停底色一出来图标就偏了。

## 旧 §4 交互法

### 4.0 交互逻辑（八条）

1. **卡片是状态，不是盒子。** 默认一切直接放在底色上。只有「当前的」「正在处理的」「临时的」才是一张卡片。一个视图里的卡片最多一两张；不为了整齐套卡片，卡片里不套卡片。
2. **一组只有一个当前项。** 列表与侧栏的同色加深底直接换到新项（不滑动）；只有分段切换、标签页的白底滑块沿轨道滑过去。悬停只是 `bg-hover`。动画先按频率决定动不动，曲线与时长照 §5.2（`ui/ease`），不用 ease-in。
3. **凹槽永远是凹槽。** 输入框聚焦时槽底变白、外圈蓝色聚焦环（`fieldSurface`），不浮起来；选择器展开时同理。
4. **按下即压平。** 凸起的东西按下时失去阴影（`active:shadow-pressed`），实心主按钮按下微缩 `scale-[0.98]`。
5. **光标停留不等于选中。** 菜单、命令面板里键盘或指针停留的项用 `bg-hover / bg-active`；「当前」的中性加深底只留给真正选定的东西。
6. **从哪来，回哪去。** 菜单从触发元素展开、收回；抽屉从哪条边来退回哪条边；居中的对话框、命令面板在原地浮起（淡入并从 0.98 放大）、原路沉回；手风琴沿折痕向下展开、向上折回；侧栏塞到屏幕左边之外，从左边缘浮出。消失比出现快一档，曲线相同。焦点同理：关掉后回到打开它的元素；受控打开、没有 Trigger 的对话框（命令面板、全屏预览）自己记下打开前的焦点，关时还回去。
7. **最多三层。** 底色 → 卡片 → 浮层。
8. **空状态只放字。** 空状态只有几行字和一个动作，不画插图、不套卡片。

## 旧 §5 动效法（并入内核 K3 与 `DESIGN.md` §4.2；裁定 1–10 编号保留）

（2026-10-01 重写，用户：「动画要有逻辑」。盘点见 `docs/研究/动效-盘点.md`，参考 uiarc 的动效文档。数值真源 `ui/ease.tsx`、`ds-tokens.css`。）

### 5.0 一条原则：动效说清因果

每个动画先回答三件事，答不出就不动：

1. **谁引起的**：指针点击 · 指针直接操作（拖、滑、按住）· 键盘 · 系统自己发生（加载完、通知到）· 滚动进入 · 时间（进度、倒计时）。引起者决定动不动、怎么动（§5.1）。
2. **从哪来**：触发它的那个东西（菜单从按钮长出来）、所在的边（抽屉从右边进）、原来的位置（列表项让位）、变形前的自己（按钮长成面板）。没有平面上的起点的（居中的对话框、命令面板）只在原地浮起：淡入并从 0.98 放大，不位移；连这个也说不出的，只淡入。
3. **到哪去**：落点明确（指示块停在新选项下）；离开走原路（菜单缩回按钮、抽屉回到右边）；被移走的东西让周围补位，不凭空消失。

动画只有五个目的：反馈、空间连续、状态指示、避免突变、（仅首次）解释（emil）。

### 5.0a 能用代码做的动效，就用代码做

能用代码做的动效，就用代码做。交互动画按 §5.2 选弹簧，其余按该节选 CSS。

代码动画可打断，跟着状态走；主题、尺寸和减少动态也由同一份代码响应。GIF / 视频把画面定死，不能像弹簧那样中途反向；它们不自动适配深色与 `prefers-reduced-motion`，位图缩放还会失真。Lottie / Rive 虽可用播放器控制，也不能替代界面自身的状态与动效逻辑。

只有插画性质、无交互、与状态无关的内容，才允许使用这些资源。元素必须标 `data-illustration`，同时提供静态 `poster` 或 `data-static-src` 替身；开启减少动态时停帧并显示静态内容。标记和路径不能代替实际的停帧逻辑。

| 时间 | 进度线、长按进度、倒计时、转圈、骨架屏、跑马灯 | **匀速**：进度类 linear；循环类对称缓入缓出；减少动态时停住，或只留明暗呼吸 |

### 5.2 五条弹簧，按物体的性格选

交互动画一律用 motion 的物理弹簧（可打断：中途反向从当前位置、当前速度接着走）。写成 stiffness / damping（`ui/ease` 的 `spring()` 换算），不写 visualDuration / bounce。

| 弹簧 | 值（看起来多久 · 回弹） | 给谁 | 例子 |
| --- | --- | --- | --- |
| **snappy** | 0.22s · 0.15 | 小东西换位置、换状态（物体 ≤ 48px） | 开关圆钮、勾、单选点、图标变形、数位滚动、菜单 / 提示 / 弹出层弹出、按压回弹 |
| **smooth** | 0.35s · 0（从不过冲） | 面板、高度、布局补位；**位移 > 200px 只能用它** | 折叠的展开与收起、抽屉、对话框、命令面板、侧栏、列表增删、toast 出现 |
| **morph** | 前沿 snappy + 后沿 smooth（一对） | 同一个物体变形，**只管外框**：两条边各走一条弹簧，途中拉长约 40%、到位缩回；圆角、底色跟后沿 | 分段 / 标签的白块、开关圆钮按住拉伸、按钮长成面板、胶囊长成菜单 |
| **follow** | 0.125s · 0.14 | 跟手：手指在哪它在哪 | 拖滑块、拖抽屉、滑动行、拖 toast、按住卡片 |
| **release** | 0.40s · 0.25 | 松手后带着速度落定；位移 > 200px 时改用 smooth；甩出的速度封顶到投影距离（0.3 秒走完剩余），撞到端点就停住、不冲出轨道 | 滑块松手弹回、滚轮停格、行弹回、卡片放下、开关拖动松手 |

**按压**复用 snappy：指针按下 snappy 压下（阴影直接压平，`usePressScale` 给元素加 `data-pressed`），松手同一条 snappy 弹回；开头位移不超过全程 15%；键盘不缩放；减少动态时直接压到位、直接弹回，没有过渡。压多深按大小定，让压下去的像素量相近：按钮、白块 0.97；小于 24px 的勾选框、单选点 0.9，日历格 0.95；滑块圆钮按住反而放大到 1.1（手指盖着它，要让它露出来）。

CSS 只留三件事（不会被打断、不跟手的）：

| 用途 | 时长 | 曲线 |
| --- | --- | --- |
| 颜色、悬停、描边 | 150（`--ds-dur-fast`） | `ease-ds` |
| 淡入 / 淡出（没有位移的出现消失） | 进 200（`--ds-dur-base`）· 出 150 | `ease-ds` |
| 出场（只在展示组件，每页一次） | 区块 400 · 截图 700 · 首屏 1200（`--ds-dur-enter / media / hero`），错落 50 | `ease-ds-expo`、截图 `ease-ds-media`；标题 rise 位移用 snappy，防首帧冲出 |

`ease-ds` = `cubic-bezier(0.23, 1, 0.32, 1)`（强 ease-out，emil）。不用 ease-in。时间驱动的用 `linear`。

### 5.3 同拍、不动、可打断、减少动态

> **已废止**：本节「滚动位置（换页立即回顶）」。现行：换页 PUSH 回顶、POP 还原（内核 K3）。本节与 5.3a 的实现坑待下沉到 `ease.tsx`、`popup.tsx` 文件头。

- **同拍**：一次动作里所有会动的东西同时开始，用同一条弹簧（或 morph 的一对）。颜色是反馈，可以先到（150ms），但位移、缩放、高度必须同拍：例如手风琴的箭头和面板同一条 smooth，勾和底色同一刻开始。分段 / 标签的文字始终用文字色；当前项靠白块，不插值字色。
- **绝对不动**：正在读的正文、列表结构与行高、相邻导航项、滚动位置（换页立即回顶）、功能图标语义、光标形态（变形期间内部 `inert`）、换主题（不过渡；唯一例外是 `theme-switch` 的可选 `transition`：日食 / 中缝 / 升起，默认关，只在指针触发、浏览器支持 View Transitions、没开减少动态时播放，用户 2026-10-01 按推荐定）。
- **可打断**：会被反悔的动作（开关、分段、标签、滑块、展开收起、按压、数字滚动、抽屉）一律弹簧；CSS 关键帧只给不会反悔的一次性出场。会被中途反向的位移（旋出、展开），x / y / scale 用各自的 motion value 拼 transform，不把整串 transform 字符串交给 `animate`：字符串插值拿不到分量速度，反向第一帧会折回；错落的 delay 只给从静止出发的那一次（2026-10-04 环形菜单）。
- **从第一帧计时**：和挂载同一刻起步的弹簧与淡入（打开面板、看图器飞出、卡片展开）写 `animate(值, 目标, { ...SPRINGS.x, ...FROM_FIRST_FRAME })`。motion 默认从创建那一刻计时，挂载的长任务会算进动画，第一帧就跳到半程（2026-10-04 实测 25%，CPU 降速 4 倍 95%）。只用于独立的 MotionValue，不放进 motion 组件的 transition。`spring-audit` 查首帧步长 ≤ 15%。
- **原路返回**：离开的动画是进入的倒放——同一个原点、同一个方向；变形的面先把内容淡出再缩回触发器，触发器在外框到位时才出现。
- **减少动态**：保留终态、焦点、颜色和 ≤ 200ms 的透明度；去掉位移、缩放、拉伸、视差，循环停住或只留明暗呼吸。**每个组件自己读 `useReducedMotion()`**，不依赖使用方根部的 `MotionConfig`；悬停动效（非颜色）包在 `(hover: hover) and (pointer: fine)` 里。
- **实现约束**：只动 `transform`、`opacity`、`clip-path`（例外见裁定 8、9）；不写 `transition-all`、`scale(0)`、`left / top / margin / padding` 动画；父级 CSS 变量不驱动子元素 transform。换排法（网格 / 列表 / 瀑布）的 FLIP 只平移不缩放：内容会重新折行，非等比缩放会把字压扁（2026-10-04 布局集合）。
- **退场的两个坑**（2026-10-02）：① 用 `usePresence` 自己管退场时，键盘这类 0ms 分支不能在 layout effect 里同步调 `safeToRemove()`——`AnimatePresence` 在自己的 layout effect 里才登记退场，比子项晚，同步调用会被忽略、元素永远留在页面里；写 `queueMicrotask(() => safeToRemove())`（提示、提示条、轻提示踩过；检查：`scripts/presence-e2e.mjs`）。② `AnimatePresence mode="popLayout"` 的子项是自定义组件时，必须把 `ref` 交给里面的 motion 元素，否则新旧两份文字上下叠着把容器撑高（轻提示踩过）。

### 5.3a 动效的底层法则：不掉帧（2026-10-05，用户：「从第一性原理和底层代码算子优化出发」）

弹簧选对了还会卡，卡的原因只有几种，写代码时逐条避开；`motion-perf` 检查查它们。

1. **渲染里不读布局。** React 渲染函数里不调 `getComputedStyle`、`getBoundingClientRect`、`offsetWidth` 这类会强制排版的接口。要起点尺寸，就平时用 `ResizeObserver` 记住，或取正在跑的动画的当前值。
2. **动画从提交的下一帧开播。** 状态一变，这一帧先把元素钉在起点；下一帧（`requestAnimationFrame`）再开始弹簧和淡入。这样提交本身花的时间不会被算进动画，第一帧不会跳过一截。键盘触发仍是 0ms，减少动态照旧。
3. **逐帧只改合成层属性。** 动画里每帧只改 `transform` 和 `opacity`。必须改尺寸的（按钮换文案的宽度、折叠的高度），只改这一个元素，并且隔离它对周围的影响：`contain: layout`，或者让兄弟元素不跟着重排。
4. **昂贵的绘制只在动画期间提升。** 模糊、大阴影、遮罩的变化，动画开始前加 `will-change`，结束后撤掉。模糊半径不超过 4px，只给面积小的文字层。
5. **逐帧数值不走 React。** 动画中的数值放在 MotionValue 或直接写样式，不在每一帧 `setState`；一次动作只提交一次。
6. **弹出层只挂当前需要的。** 打开时不挂整棵隐藏内容；整页样式不因为插进一个弹层而大面积重算（避免依赖 `:has()`、通配后代选择器）。

验收看两个数，开发模式和正式构建都量：正常速度下没有超过一帧（16.7ms）的长帧；每个动画的第一帧，走过的路程不超过全程的 15%。

### 9.2 刻度

#### 字号（正文 7 档，导航单独校准）

前三档是基础参数（`--base-text-*`）。界面 15、阅读 17，比值 1.13——两档要分得开（2026-09-28 排版研究：原 16/17 只差 6%，层级糊，读着累；`docs/研究/排版.md`）。

| --- | --- | --- | --- |
| `text-xs` | 13 / 20 | 400、500 | 注释、时间、分组名、表头、文字提示、刊头 |
| `text-sm` | 15 / 24 | 400、500 | 按钮、列表标题、菜单、标签页 500；表格与说明 400 |
| `--ds-text-nav` | 14 / 24 | 500 | 侧栏导航、项目名；行高 36＋项间 4（10-05 参考图校准） |

| `text-lg` | 20 / 26 | 600 | 三级标题、对话框标题 |
| `text-xl` | 24 / 30 | 600 | 二级标题（页面里的区块标题）、文章标题 |
| `text-2xl` | 30 / 38 | 600 | 一级标题 |

- **输入类控件的字用 `text-md`**（`--ds-text-field`，不算新的一档）：input、textarea、contenteditable、原生 select 里用户打的字，精确指针 15、触屏 16，行高 24。iOS Safari 聚焦小于 16 的输入框会放大整页（2026-10-02）；按钮、选择器的触发按钮仍是 `text-sm`。检查：`scripts/touch-audit.mjs`。
- 字重只有三档 400 / 500 / 600（苹方只有到 600 的这几档与 Inter 对得上：350 会被取成 Light、700 会被取成 Semibold，中西文粗细不一）：400 正文、表格正文、输入、说明 · 500 导航（`--ds-weight-nav`）、列表标题、菜单、标签页、按钮（`--ds-weight-control`）· 600 标题；当前状态不改变字重。快捷键符号画成 lucide 图标（`ui/kbd` 内部），不用字体字符；键帽只出现在快捷键一览里（§4.2）。
- 字距：正文不加负字距；标题 `--ds-tracking-display`（−0.01em，中文不宜再紧）。中西文之间自动留空（`text-autospace`）。中文标题不用 `text-balance`（会拆词）。
- 字体：标题与正文都是 Inter + 苹方（`--ds-font-sans`；没有苹方的系统用思源黑体），用户不要衬线（2026-09-25）；编号与标签 `font-mono`（Geist Mono）。数字：`tabular-nums`。

#### 文字颜色（3 档）

三档实色文字：`text-fg` = 浅色 #050505 / 深色 #f5f5f5，默认用于标题、正文、导航、列表标题、菜单、表格、标签页与普通按钮；主按钮用反色、危险动作用语义红。`text-fg-muted` = #6b6b6b / #a3a3a3，只给说明、时间、计数、分组名、占位符，各基础面 ≥4.5:1；`text-fg-subtle` = #858585（深色 #8a8a8a），只给 ≤13px、不承担信息的注释。

- **正文一律 `text-fg`**：两行以上的段落不整段用灰字（汉字笔画密，灰了就糊）。`text-fg-muted` 只给一行以内的说明、元信息、分组名与占位符。
- 文字负担（`scripts/type-audit.mjs` 检查）：一屏占字数 2% 以上的字号 ≤ 4 种、字重 ≤ 3 种；次级灰占内容区字数 ≤ 30%；600 字重 ≤ 15%；视觉字号 ≥ 12px。侧栏导航单独检查 14 / 500 / 文字色，不计入正文的主要字号种数。

#### 间距

`4 · 6 · 8 · 12 · 16 · 20 · 24 · 28 · 32 · 48 · 64 · 96 · 128`（Tailwind `1 1.5 2 3 4 5 6 7 8 12 16 24 32`）。6、20、28 来自实测：6 是图标与文字、面包屑项的内边距，20、28 是列表与邮件式应用里的固定位置；128 只给页面底部。
例外只有 2px：轨道内边距（`--ds-pad-track`）与紧挨的行之间（`gap-px` / `gap-0.5`）。
- 装东西的面不在这里取数：卡片、面板、对话框、展示台的内边距和里面的间距一律 `p-inset` · `gap-group` · `gap-item` · `gap-part`，由容器宽度算（§3.0、下表「容器内边距」）。
- 刻度外的写法一律不许：`text-[13px]`、`rounded-[5px]`、`px-2.5`、`gap-5` 之类。检查：`grep -rnE "text-\[[0-9.]+px\]|rounded-\[[0-9]+px\]|\b(p|px|py|pt|pb|pl|pr|m|mx|my|mt|mb|ml|mr|gap|gap-x|gap-y)-(2\.5|3\.5|9|10|11|14)\b"` 为空。

#### 圆角红线

- 只用语义圆角类。禁止 Tailwind 默认圆角类、任意值、手写像素圆角与自造数。
- 实际内圆角 = 基础外圆角 × corner-k − 实际内边距。间距不乘 k。
- `--ds-r-*` 外圆角 token 已含 k；使用它时只减实际内边距，不再乘 k。
- 胶囊 / 正圆里的选中底色与控件也是胶囊 / 正圆。
- 方角格子里不放贴边的圆角元素。容器给圆角并留缝，或里面的元素不圆。
- 输入框、按钮用 `rounded-control`，行用 `rounded-row`。卡片里贴内边距的面按 `--ds-r-in` 派生；角上的动作按同心 token 派生。
- 表格 / 网格的格子不单独圆角，只有整组外框圆。
- 每个圆角三问：外面是谁？它的实际圆角多少？我离它多远？我的实际圆角 = 它的实际圆角 − 距离。
- 交付前跑 `radius-audit` 与 `radius-static`。别的项目无法跑脚本时，逐个元素按三问自查，在汇报中列出容器、外角、距离、内角。
- 反例：胶囊工具条里的选中项用圆角方块，内外轮廓不同心。
- 反例：方格里的编号输入框贴边且单独圆角，四角露出下层底色。

#### 圆角（实际内圆角 = 基础外圆角 × corner-k − 实际内边距）

阶梯由基准圆角 `--base-r-base`（10）派生；浏览器支持 `corner-shape` 时整体 ×1.5 并换成连续圆角（超椭圆 `superellipse(1.6)`，实测 n≈3，拐角弯曲范围约为控件高的 40%），不支持时就是下表的普通圆角（`--base-corner-k`、`--base-corner-shape`）。`rounded-full` 不受影响，圆点与头像保持正圆；组件自带语义圆角、使用方再写 `rounded-full`（圆形图标按钮）时同样是正圆：语义圆角规则排除 `.rounded-full` / `.rounded-none`（2026-10-04，`corner-audit` 查）。

| 类 | 值 | 用在 |
| --- | --- | --- |
| `rounded-sm` | 8 | 复选框、键帽、标签、行内代码 |
| `rounded-control` / `rounded-row` | 10 | 按钮、输入框、导航项、列表行 |
| `rounded-track` → `rounded-track-item` | k=1：12 → 10；k=1.5：18 → 16（内边距 2） | 分段切换、标签栏 |
| `rounded-popover` → `rounded-popover-item` | k=1：14 → 8；k=1.5：21 → 15（内边距 6） | 菜单、下拉、命令面板 |
| `rounded-card` | 18（内部控件仍用 `rounded-control`） | 卡片、对话框、抽屉、提示条 |
| `rounded-full` | 不乘 k，保持 round | 正圆；高 ≤48 的单行胶囊；开关 / 滑块圆钮；进度条 / 滚动条。高 >48 的非正圆面禁止 |
| `rounded-mark` | 4，不乘 k | 小色块、角标、图表柱顶 |
| `rounded-tile` / `rounded-media` | 14 × k | 展示卡、媒体外框 |
| `rounded-control-in` / `rounded-control-action` | control − 4 / control − (控件高 − 24) / 2 | 控件内钮 |
| `rounded-control-tag` / `rounded-track-tag` | control / track − (控件高 − 20) / 2 | 控件 / 轨道内的标签 |
| `rounded-sm-in` | sm − 4 | 小件角上的角标 |
| `rounded-row-action` | sm − (行高 − 24) / 2 | 行内动作 |
| `rounded-card-in` / `rounded-window` | card − 12 / card − gutter | 卡片内面、分栏内窗 |
| `rounded-card-control` | card − 4 | 卡片角上的控件 |
| `rounded-inherit` / `rounded-none` | 继承 / 0 | 重合状态层 / 方格 |

- 成对变量：`--ds-r-popover` / `--ds-pad-popover` → `rounded-popover-item`；`--ds-r-track` / `--ds-pad-track` → `rounded-track-item`。贴着卡片内边距的面用 `rounded-in`：`--ds-r-in = max(sm, card实际圆角 − 实际内边距)`；sm 下限是此内面的例外。
- **角落同心**（detail.design「blur trick」）：圆角容器角上的按钮离两条边一样远，圆角 = 容器圆角 − 间距；胶囊里的图标模糊后贴着同心内轮廓（离端点 = 离上下，`--ds-pad-icon`）。这时不用 `edge-*`。

#### 组合（产品实测；证据见研究资料 `docs/研究/`）

- **对齐的是字，不是盒子**：容器比它旁边的文字列两边各宽出自己的内边距，框里的字和列里的字在同一条竖线上（对话输入框 = 正文列 + 2 × 20）。
- **一张卡片里只有两条竖线**：搜索行、结果行、分组名共用图标线和文字线（命令面板：搜索行左内边距 = 面板内边距 + 行内边距）。
- **当前项同色加深**：实色灰填充 #e9e7e7（浅色）/ #262626（深色），无凸影；悬停叠黑 4%，永远比当前轻。凹槽轨道保留白底滑块。
- **行高固定**：两行的条目（标题 + 灰色补充）也塞进同一个行距，不把行撑高。菜单项也一样：两行信息写成一行「名字 · 右侧次要文字」（2026-10-04 工作区菜单）。
- **角落里的控件离两条邻边一样远**（输入框里的发送钮、按钮里的键帽）。
- **导语在前、证据贴近、留白在后**：导语第一句文字色、其余次级灰；关键数字紧贴导语（16）；之后才是整页最大的留白（48）和分节线。
- **关键数字只画线**：1px 外框（`fg-subtle`）+ 上下缩进的格间竖线（`line-strong`），数字 / 说明 / 补充三档浓度；不用底色、不套卡片。
- **刊头**：页面标题上方一行小字，左写类别、右写状态与日期，加宽字距（`tracking-widest`）、次级灰。
- **分节**：新的一节 = 上方 48 + 通栏细线 + 32 + 标题；节内块间 8。
- **对话**：用户气泡右缘对齐输入框右缘，最宽八成列宽，圆角大于单行高的一半（一行是胶囊）；一问一答之间 48；输入框是浮起的白卡，离底 24。助手模式同样：用户的话是右侧浅灰气泡，助手的回答直接写在底上。

#### 材质（一个光源，在正上方）

界面有高度，不是贴图。每个表面只能处在下面六个高度之一，高度决定它的阴影，也决定它怎么被操作：

| 高度 | 类 | 光影 | 用在 | 手感 |
| --- | --- | --- | --- | --- |
| 凹 | `bg-well shadow-inset` | 浅色黑叠 1.2%、深色白叠 3%；1px 内边线 | 输入框、轨道、进度条、选择控件空框 | 可以填、可以拨 |
| 平 | `bg-canvas` / `bg-sidebar` | 无 | 页面白烟 `#f9f8f7`、侧栏 `#f5f3f2`；Card / Surface 页级默认透明 | 可以读 |
| 凸 | `bg-card shadow-raised` | 1px 内边线 + 下投影 | 键帽、开关圆钮、滑块圆钮、轨道里的当前项 | 可以按 |
| 实心 | `bg-action`（主按钮） / `bg-primary`（选择点） | 明确实底，无模糊影；按钮文字色，选择点强调蓝 | 主按钮、确认面的危险确认、选中的复选框和单选 | 可以按，最重要 |
| 浮 | `bg-card shadow-card` | 细边 + 柔影 | 输入卡、临时工具、浮层内的 Card / Surface | 临时抬起的小面 |
| 悬 / 罩 | `shadow-popover` / `shadow-overlay` | 更大更虚的投影 | 菜单 / 对话框、抽屉 | 暂时盖在上面 |

- 次要按钮白底 + 1px 中性内边线，无投影；第三级才用浅灰块。凸起只给轨道滑块、键帽和圆钮。阴影变量不写 `none`，用 `0 0 #0000` 保留 Tailwind 焦点环。
- 按下 = 凸起落回平面：`shadow-raised → shadow-pressed`、`shadow-solid → shadow-solid-pressed`，同时 `scale-[0.98]`。
- 凹槽永远是凹槽：聚焦时槽底变白（`bg-card`）并加外圈蓝色聚焦环，不会“浮起来”。
- 圆钮被按住时朝要去的方向伸长（开关 16 → 20），拖动的滑块圆钮放大到 1.1；松手弹回。
- 凸起的东西放在凹槽里（分段切换的滑块、开关圆钮），不会叠在另一个凸起上。
- 不画纹理、不画材质图片；拟物只靠这一套光影和手感。

### 9.3 颜色

只用语义类：`canvas sidebar card well hover active fg fg-muted fg-subtle line line-strong action action-fg action-hover primary primary-fg accent accent-text tertiary tertiary-hover selected nav-current panel menu notice table-head table-line focus warning danger success scrim inverse inverse-fg viewer`。
强调图形蓝 `primary / accent / focus` 为 `#1378fe`，深色 `#3b8dff`；只给小面积关键状态。链接用 `accent-text`，浅色 `#1066d9`，基础面与选中底上 ≥4.5:1；文字提示用 inverse（黑底白字）。
**按钮默认用文字色实底**：`Button` 默认 `variant="primary"`，`bg-action text-action-fg`；浅色 `#050505` / 白字，悬停 `#262626`；深色 `#f5f5f5` / `#121212` 字，悬停 `#d9d9d9`。secondary 白底实线；tertiary 灰填充；ghost 无底；danger 白底红字，danger-confirm 只用于确认面里的红实底确认。每组一个主动作。

页面大面用 canvas，Card / Surface 默认透明；对话框与抽屉同纸底。浮层内小面、输入卡、浮动工具用 card + 1px 实色边 + 柔影。菜单与轻提示为 card 叠 tint 5%；表头为 canvas 叠 0.8%；表格行线与结构线同为实色 line。
状态色只出现在小面积上（圆点、图标、危险按钮）；状态文字保持灰阶。
不写具体色值（`#xxx`、`text-gray-500`、`bg-[#…]`）、不自创调色板；深色只靠 `<html data-theme="dark">` 切换设计变量，组件里没有主题分支。

### 9.6 图标

- 常见功能用大众一眼认得的图标隐喻（lucide 里现成的），不为差异化自创图标；新用到的图标加进 Su Design 的图标页清单 `src/site/icon-list.ts`。
- 网格 16×16，内容区 12×12（2–14），线宽 1.5，圆头圆角，只用线不用面。例外（2026-10-02）：开关型的「已收藏 / 已点赞」可以填实（`fill-current`），用形状而不只靠颜色表示状态；未选中时仍是线。
- 会变形的图标（`MorphIcon`）：每个恰好三条线，不用的收成中心点；第 1 条偏竖、第 2 条偏横、第 3 条备用；同形状不同方向的属于一个旋转组，组内只旋转。
- 状态会互相切换的地方用 `MorphIcon`（展开 ↔ 收起、菜单 ↔ 关闭、播放 ↔ 暂停、加 ↔ 对勾）；其余用 Lucide，全局统一成 1.5px 线宽。
- 图标默认 `text-fg-muted`，悬停或当前时 `text-fg`；图标按钮必须有 `aria-label` 和 Tooltip（对话框、抽屉的关闭按钮例外：只要 `aria-label`）。
- 弹出层（提示、菜单、选择器、弹出框）离屏幕四边 ≥ 8（`collisionPadding={8}`）。提示落在空白处或伸进旁边一块，不盖住同一块里的别的控件：面板右上角的按钮提示往左，一列行末按钮往左，侧栏顶上的按钮往右（`popup-audit`）。
- 一行首尾的无底色按钮用 `edge-start` / `edge-end`，推出去的是它自己的内边距（`--ds-edge`，按钮各尺寸已写好）；末尾是窄图标时加 `--ds-ink-inset`（⌄ 3、› 5）。`edge-*` 只给无底色按钮：实心、灰底按钮不推，按钮外沿就是内容线（2026-10-04 项目页头）。
- 按钮里的图标不加悬停动画（用户 2026-09-28：试过每个图标配一个动作，硬加奇怪；确有必要的地方再单独加）。代码里用到的 lucide 图标都进图标页（`src/site/icon-list.ts`，`icon-audit` 查）。

### 9.8 文案

占位符只写数据形状，不写「回车」「按住」或快捷键操作。

标题一个词或一句话；按钮写动作本身（“删除项目”，不写“确定”）；不写理念和比喻。界面不讲设计理念、不解释为什么；删到不能再删，留白比字多。

**提示三问**（用户 2026-09-28：「『用管理员开给你的账号登录。』这种废话不应该有，用文字提醒要极度克制」）：说明句默认 0。一句提示只有三问全过才写——
1. **不写会做错吗**：删掉它，用户会做错，而且代价高或不可撤回（丢了能重来、能撤回的，不算）。
2. **界面说不了吗**：控件、标签、状态、位置、占位都表达不了这个意思（按钮已经写了「生成 Key」，就不再写「还没有 Key」）。
3. **此刻需要吗**：就在用户做决定的那一刻、那个位置。常驻的规则说明（「至少 8 位」）改成违反时才出现的错误。

能写的只有三种：出错与状态反馈（发生后才出现）、不可撤回操作的确认框里一句后果、数据本身（邮箱、时间、数量）。

**不写的**（用户 2026-09-29：「少文字少提示……这种是红线」「这些都是很恶心的解释性文字」）：页面、区块、设置项下面的说明句；标题后面括号里的解释（「来源更新（今天 / 近两天）」→ 只写「来源」，数字自己说明）；空状态的说明句（只留一句标题和至多一个动作）；「热度最高」「最新」这类给推荐理由贴的标签；键位和操作说明（§4.2）。代码里每一句界面提示，上一行写 `// 必要提示：` 和它过三问的理由，`scripts/copy-audit.mjs` 查。

## 2026-10-16 文字 token 实色规则只抓真透明

## 2026-10-16 先例关卡只认脚本真正写的文件

起因：用 Bash 跑一段 python heredoc 改 `scripts/static-gate-audit.mjs`（不是界面文件），替换进去的用例里写着 `web/src/pages/e.css`、`web/src/styles/app.css` 等测试文件名，先例关卡报「要改的是界面（e.css、app.css…）」拦下。原因在 `shellWrites` 第 4 条：命令里只要出现 `writeFile` / `open(…'w')` / `.write(` / `write_text`，就把命令里所有像界面文件名的字符串都当成写入目标。修它的会话里又被装着的 1.7.1 拦了两次（node 脚本从会话记录里抽命令，字符串里带「e.css」；heredoc 往本文件追加这一条）。
裁定（`plugin/hooks/precedent-gate.mjs` 的 `scriptWrites`）：脚本里写文件只认写入调用的目标路径，脚本里别的字符串（替换进去的内容、注释、提示文字）不算。
- 认这些调用：`writeFile` / `writeFileSync` / `appendFile(Sync)` / `createWriteStream` / `Bun.write` 的第一个参数；`open(路径, 'w' / 'a' / 'x'…)`（第二个参数或 `mode=` 是写模式才算，只读的 `open(p)` 不算）；`Path(…).write_text(` 与 `Path(…).open('w')` 前面的对象。`.write(` 本身不再算：它写的是 `open` 打开的那个文件，`open` 已经认过。
- 路径是变量时顺着命令里的定义找，最多三层：赋值（`p = …`、`p, q = …`）；`for` 循环，含拆包（`for p, pairs in edits.items()`、`for (const [file, reps] of specs)`）；函数参数（`def edit(p, pairs)` → 每处 `edit('x.tsx', …)` 同一位置的实参）。右边按括号配平读到语句结束，跨行的字典、列表也读全。
- 路径来自命令行参数（`sys.argv`、`process.argv`）时，只看运行脚本的那条命令（python / node / bun / deno 开头）的参数，先去掉 heredoc 正文和 `-c` / `-e` 后面的脚本；`"$f"` 照样顺着 shell 的 `for`、赋值找。

- 认不出：`join('web/src/pages', 'new.tsx')` 这种拆开写的路径只拿到 `new.tsx`，按 cwd 找项目（原规则也一样）；循环的是字典时整份字典都算，键不是界面文件、替换内容里提到界面文件名的仍会拦。
- 重定向、`tee`、`sed -i`、`cp` / `mv` 三条没动。
用例：`precedent-gate-audit` 加十二条：放行三条（python / node heredoc 改 .mjs、内容里提到界面文件名；node 经命令行参数写 .txt、脚本和后面的命令里提到 .tsx），python 只读 .css 放行；仍拦八条（python 直接写、经变量、经改文件函数、经跨行字典循环、经命令行参数，pathlib 写，node 写、经拆包循环写界面文件）。证据：`docs/验收/2026-10-16-先例关卡误拦/`（`run.mjs` 跑用例审计、回放当天被误拦的两条原命令、11 种改坏的反证；`compare.mjs` 拿本机历史会话里的真实命令对比新旧关卡）。插件 1.7.2。
